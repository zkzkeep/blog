## 起因

[第一篇](/posts/apple-silicon-x86-windows-usb-passthrough/)和[第二篇](/posts/apple-silicon-x86-windows-usb-passthrough-2/)都在讲同一件事：在 M 系列 Mac 上用 UTM 跑一台 **x86 Windows 7**，把一个只有 Windows 客户端的加密 U 盘直通进去解锁。

不管怎么调优，速度的天花板一直没变：从 U 盘读约 2.2 MB/s，往 U 盘写约 1 MB/s。根因在于 M 芯片是 ARM 架构，这台 Win7 是**整个操作系统都在逐条翻译 x86 指令**。

最自然的出路，就是换成 **Windows 11 ARM**：

- 系统本身是 ARM 原生的，在 Mac 上靠硬件虚拟化运行，接近原生速度
- 只有厂商客户端这一个 x86 程序，交给 Windows 自带的模拟层（Prism）去跑

需要模拟的从「一整个操作系统」变成「一个程序」，理论上能快一个数量级。这篇就是实测这条路。

## 事先的判断，和一个没核实的风险

Windows on ARM 的模拟有一条硬限制，微软文档写得很清楚：**模拟只覆盖用户态程序，不支持驱动；所有内核态组件都必须是 ARM64 原生编译的。**

所以关键只有一个问题：**这个客户端要不要装自己的内核驱动？**

动手之前，我在 Mac 上对客户端做过一次静态分析：

- 主程序的导入表里没有创建服务的函数，只有「查询服务状态」
- 程序里确实有一句「驱动服务启动失败，请联系管理员」，但相邻的代码和字符串都指向一个给 Windows XP 补装 exFAT 文件系统驱动的流程，Win11 本来就自带 exFAT
- 但主程序里还**打包了一个加密过的 DLL**，运行时才解开，静态分析看不到里面是什么

当时的结论是「看起来不装内核驱动，可能性比较大，但那个加密 DLL 没法核实」。后来知道了，问题恰恰就出在这个没法核实的地方。

另一个让人乐观的信息是：单位的 x86 Windows 11 电脑能正常使用这只 U 盘，说明客户端本身兼容 Windows 11。

## 实测

用 Parallels Desktop 官方试用版装了一台 Windows 11 ARM，把 U 盘直通进去，双击启动区里的客户端，结果弹出：

> 驱动服务启动失败，请联系管理员。

不重启和重启后都试了，结果一样。

看提示猜不出原因，于是去翻 Windows 的系统日志，只看服务相关的三类事件：7045（安装了新服务）、7000（服务启动失败）、7026（引导时驱动未加载）。日志写得清清楚楚：

| 事件 | 内容 |
|---|---|
| 7045 | 客户端**往系统里装了一个服务**：类型是「**内核模式驱动程序**」，启动方式「系统启动」，文件在 `SysWOW64` 下，文件名以 `64.sys` 结尾 |
| 7000，共 6 次 | 这个服务启动失败，原因：**此驱动程序被阻止加载** |
| 7026，重启后 | 引导启动的驱动程序未加载：还是它 |

客户端运行时会给系统装一个**自己的 x64 内核驱动**，加密分区的解锁就靠它完成。ARM 版 Windows 加载不了 x64 驱动，客户端自然没法工作。

这条路走到这里就到头了，没有绕过去的办法：

- **驱动没法模拟**：Prism 只翻译用户态代码，内核里跑的必须是 ARM64 原生代码
- **在 ARM 上模拟一整台 x86 Windows 11**：那就回到了现在 Win7 的老路，而且 Win11 比 Win7 重得多，只会更慢
- **只剩两条路**：一台真正的 x86 电脑，或者等厂商出 ARM64 版驱动

## 回头看，几件事都对上了

这个结论顺带解释了前两篇里几个当时没想通的现象：

- **为什么 Win7 里每次打开客户端都会弹 UAC。**一个「绿色版」U 盘客户端本来不该需要管理员权限，它要的权限，就是用来装这个驱动的
- **为什么单位的 Windows 11 能用。**那是 x86 芯片的电脑，x64 驱动可以正常加载。「能在 Windows 11 上用」不等于「能在 Windows 11 ARM 上用」，中间差的正是这个驱动
- **为什么 Win7 方案能用。**UTM 的 TCG 模式模拟的是一整台 x86 电脑，从内核到程序全部在模拟层里，驱动也一样能加载。慢，但完整

## 顺手记两件小事

**几十块的「终生激活码」。**测试期间看到网上有卖 Parallels 「终生激活码」的，只要几十元。官方买断版的价格在 200 美元以上，这个价格本身就说明问题。问清楚之后，激活要在终端里运行卖家给的命令，那就是破解。这台 Mac 恰好要中转单位 U 盘里的资料，最不该做的就是让来路不明的命令改系统。最后用的是官方的 14 天试用，验证一个「能不能用」完全够了。

**卸载 Parallels 后，启动台里冒出一堆不认识的应用。**Edge、Outlook、OneDrive、纸牌游戏、ODBC 数据源……一共 55 个，全是 Windows 11 里的软件。Parallels 会给虚拟机里的每个 Windows 程序在 Mac 上生成一个快捷方式，放在用户目录下的 `Applications (Parallels)` 文件夹里，另外在 `~/Library/Parallels/Applications Menus` 下还有一份菜单。删掉虚拟机和 Parallels 本体之后，这两个文件夹要手动清掉。删之前可以核对一下这些快捷方式的 Bundle ID，都是 `com.parallels.winapp.<虚拟机编号>.…` 的形式，不会误删 Mac 上真正装着的 Office。

## 结论

**在 Apple Silicon 的 Mac 上，这只 U 盘只能用「完整模拟 x86」的方式来用，也就是现在这台 Win7。**

判断一个 Windows 程序能不能在 ARM 版 Windows 上跑，比起「它是不是 exe」，更关键的问题是：**它要不要往内核里装东西？**普通程序靠模拟层大多能跑；一旦带了自己的内核驱动（加密盘、安全软件、虚拟光驱、反作弊、一些 USB 设备工具），就必须有 ARM64 原生版本，否则没戏。

验证这件事，最快的办法不是猜，也不是静态分析，而是**装上跑一次，然后去翻系统日志**。服务相关的那三个事件编号，会直接告诉你它装了什么、为什么没加载成功。

至于速度：前两篇的调优已经把这条路走到头了。日常几十 MB 的文档表格，几分钟以内搞定，够用。真需要更快，就得换一台 x86 电脑，那就不是在 Mac 上折腾能解决的事了。
