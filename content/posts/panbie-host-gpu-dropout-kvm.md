站里"一键顺控视频双确认"系统用的视频判别主机，9 月上旬黑屏了半个多月。厂家先后寄来一套 DVI 的 KVM、一套 VGA 的 KVM，结论始终是"KVM 坏了"，但说不清为什么坏。最后我们自己一步步排查，发现 KVM 根本没坏，真正的原因是**机器里那块独立显卡在断电时"掉线"了**。

这篇把整个来龙去脉记下来，包括走过的弯路。敏感信息（IP、端口、账号密码、设备序列号等）都已去掉。

## 一、设备和接线

先交代清楚这台机器，后面的现象才好理解：

- 主机：华为 2288H V5 服务器，装的是凝思安全操作系统 V6（Debian 系，内核 4.9，X Server 1.16）；
- 显卡有两块：一块是**主板自带的管理显卡**（只有一个 VGA 口），一块是 **NVIDIA RTX 2060 独立显卡**（DVI、HDMI、DP 口）；
- 业务：一键顺控视频双确认平台、海康视频对接、AI 识别算法等，大部分跑在 Docker 容器里，另有几个服务和一个"反向隔离"客户端要手动启动；
- 显示：一路到**主控台**的显示器（高清），一路到**屏柜里的 LED KVM**（现场维护用），两边原本同时显示同一个桌面。

原厂的设计是：**桌面跑在独显上**，独显的两个口分别送到主控台和屏柜。主板那个 VGA 口其实只是个文字控制台。这一点是后来才搞明白的，也是整件事的关键。

## 二、故障经过和厂家的两次"换 KVM"

9 月上旬，这台主机运行不畅，我们按常规断电重启。重启后主控台和屏柜都只剩黑屏，左上角一个白色光标，进不去图形界面，视频判别功能也停了。

联系厂家后，厂家判断是 **KVM 坏了**：

1. **第一次**：寄来一套 **DVI 的 KVM**。接上去，还是连不上，没画面；
2. **第二次**：我们提出改用 VGA，厂家又寄来一套 **VGA 的 KVM**。这次接上"能用了"，屏柜能看到东西了，但**主控台的高清显示没了**，而且只是个勉强能用的状态。

问厂家 KVM 为什么坏，没有答案。现在回头看，第二次"能用"恰恰是个线索：VGA KVM 接的是主板的 VGA 口，绕开了独显；DVI KVM 接的是独显，所以怎么换都不亮。

## 三、自己排查：先证明系统是活的

### 1. 看开机过程

我把开机全过程拍成视频逐帧看：BIOS 自检正常，内核正常加载，RAID 卡初始化成功，各分区做了文件系统检查，日志里有"文件系统未正常卸载、自动清除脏位"的字样，说明之前确实有过非正常断电。检查完之后才黑屏。

结论：**不是硬件死机，也不是 BIOS 的问题，系统已经启动了。**

### 2. 进字符终端

黑屏时按 `Ctrl+Alt+F2`，出来了文字登录界面，能正常登录。看了几样：

- `df -h`、`df -i`：磁盘和 inode 都很空，不是存储满了；
- `docker ps`：十几个业务容器全在运行；
- `ip a`：各网口地址都正常。

到这里基本确定：**系统和业务都活着，缺的只是图形桌面。**

### 3. 图形界面为什么起不来

`systemctl status lightdm` 显示图形登录服务在**反复启动、崩溃、再启动**，最后被系统放弃。看 X 的日志，报错只有一句：

```
(EE) Fatal server error:
(EE) no screens found
```

也就是 X 找不到可用的显卡。再看 `/etc/X11/xorg.conf`，里面指定用 `nvidia` 驱动、显卡在 `PCI:134:0:0`（也就是 `86:00.0`）。于是查显卡：

```
lspci -d 10de:      # 列出所有 NVIDIA 设备 → 空的
nvidia-smi          # 报错：无法与 NVIDIA 驱动通信
lsmod | grep nvidia # 空的，驱动没加载
```

`lspci` 里只剩主板那块管理显卡，**NVIDIA 显卡在 PCIe 总线上"消失"了**。卡明明插在机器里，系统却看不到它。这就是黑屏的根源：显卡掉线 → X 找不到屏幕 → 图形界面起不来。

## 四、冷断电：让显卡重新"上线"

同事一开始不信："显卡肯定在，之前都好好的。"确实，卡还插在槽里，但断电冲击会让 PCIe 链路没重新初始化，系统就认不到它。而之前的几次都是**热重启**，插槽一直带着待机电，掉线的卡不会自己回来。

这里还有个坑：服务器执行 `poweroff` 以后，**电源灯只是从绿变黄，并不会灭**。这是待机状态，主板和 BMC 还在供电，等于没断干净。

正确做法：

1. 先把默认启动改成文字模式，防止重启后又进图形崩溃循环：`systemctl set-default multi-user.target`；
2. `poweroff`，等电源灯变黄；
3. **到机器背后，把两根电源线都拔掉**，等 30 秒到 1 分钟；
4. 插回电源线，按前面板电源键开机。

开机后再 `lspci -d 10de:`，NVIDIA 显卡回来了。`nvidia-smi` 也正常：驱动 510.60.02，显存 8G，温度、功耗都正常。**显卡没坏，只是被断电"打掉线"了。**

同事后来问过一句："我之前也拔过电源线等了一分钟，为什么还是没图形界面？"原因是冷断电只负责让显卡重新被识别，图形界面还要靠后面的软件配置恢复。判断冷断电成没成功，看 `lspci -d 10de:` 能不能列出显卡就行，不要看有没有图形界面。

## 五、恢复过程中踩的几个坑

### 坑 1：桌面在哪个显卡上，决定了哪个口有画面

排查中为了先看到桌面，我曾把 `xorg.conf` 临时挪走，让 X 自动用了主板的管理显卡。结果：

- 屏柜（接主板 VGA）能看到桌面，但分辨率被锁死在 1024×768，发虚；
- 主控台（接独显 DVI）黑屏。

后来把 NVIDIA 的配置还原回去，桌面回到独显上，**主控台的 DVI 高清一下就出来了**，屏柜又只剩文字。这才彻底想明白：主板 VGA 口和独显桌面不能同时给两块屏用。系统同一时刻只有一个前台终端，桌面占着独显，在屏柜上按 `Ctrl+Alt+F2` 切终端，反而会把主控台的桌面切走。

中间也试过给主板显卡换 `modesetting` 驱动来提分辨率，在这台老版本 X 上起不来，放弃了。

### 坑 2：画面回来了，视频却拉不到

桌面恢复后打开判别平台，能登录，但视频窗口全是灰的，提示"GVS下级HikAdapter服务请求异常"。

- 海康对接服务的进程其实在跑，日志显示"启动成功"；
- 我开着 `tail -f` 实时看它的日志，同时在网页上点摄像头，**日志一行都不动**，说明平台的请求根本没到这个服务。

回头翻厂家留在桌面上的"启动说明"才发现：**这台机器每次重启后，都要手动跑两个启动脚本，再启动反向隔离客户端**。之前一直黑屏，这一步从来没做过。按说明跑完，等平台重启完（中间网页会短暂报 502），视频就出来了。

### 坑 3：关掉终端，网页 502

算法服务是在终端里**前台运行**的。有一次顺手把那个终端关了，网页马上变成 502 Bad Gateway。重新跑一遍启动脚本就好了。从那以后记住：**跑算法的那个终端只能最小化，不能关。**

### 坑 4：AI 算法其实没用上显卡

算法启动时有两行警告：CUDA 不可用，只能用 CPU。顺着查下去：

- CUDA 需要 `/dev/nvidia-uvm` 这个设备节点，`nvidia-smi` 不会创建它，用 `nvidia-modprobe -u -c 0` 补上了；
- 补上之后还是只能用 CPU。原因是 Docker 里只有默认的 `runc` 运行时，**没有装 NVIDIA 的容器运行时**，算法容器只拿到了显卡设备，拿不到驱动库。

这很可能从部署那天起就是这样，不是这次故障造成的，识别功能照样能用，只是慢一些。这个改动涉及厂家的专用镜像，交给厂家处理。

## 六、双屏恢复：独显一分为二

原来"两边都能看"的状态，要靠独显同时驱动两个口。主控台的 DVI 已经好了，屏柜只吃 VGA，而独显没有 VGA 口，所以买了一个 **HDMI 转 VGA 的转接头**：

- 独显 DVI → DVI KVM → 主控台显示器；
- 独显 HDMI → HDMI 转 VGA → VGA KVM → 屏柜 LED 显示器。

接好以后，用 root 打开 `nvidia-settings`，在 X Server Display Configuration 里能看到两台显示器。默认是**扩展模式**（HDMI 那块排在主控台右边），把 HDMI 那块的 Position 改成 **Same as（和 DVI 那块相同）**，点 Apply，两边就显示同一个桌面了。**整个过程不用重启桌面，视频业务也没断。**

几个细节：

- 一开始只点了 Apply 没点保存，`grep -i metamode /etc/X11/xorg.conf` 什么都查不到，重启就会丢。一定要点 **Save to X Configuration File**；
- 两块屏分辨率不一样时（1920×1080 和 1280×1024），主控台的壁纸会被画成两块、文字重复一截，任务栏也跑到了半截高度。把 HDMI 也设成 1920×1080 后就正常了；
- 屏柜那块 LED 屏比例更方，1920×1080 送过去会被拉长一点。试过用 ViewPortIn/ViewPortOut 按比例缩放加黑边，比例是对了，但字发虚：模拟 VGA 再加缩放，清晰度本来就有限。最后选了"略拉长但更清楚"的方案。屏柜主要是现场维护用，够了。

最终保存进配置文件的是这样一行：

```
Option "metamodes" "DVI-D-0: nvidia-auto-select +0+0, HDMI-0: 1920x1080 +0+0"
```

两个口都从 `+0+0` 开始，就是克隆显示。

## 七、把厂家的启动步骤做成一条命令

厂家的启动说明要切 root、分别进两个目录跑两个脚本。我把它合成了一个脚本 `start_all.sh`：

```bash
cd /home/<用户>/ && sh start_xj_srv.sh
cd /home/soft && sh start_xjai.sh
```

以后重启后的操作就是：

1. `su` 切到 root，运行 `sh start_all.sh`，**这个终端最小化，别关**；
2. 双击桌面的反向隔离客户端，最小化；
3. 打开浏览器进判别平台。

本来还想做个桌面双击图标，但现场电脑不能接外部设备，只能手敲，文件一多就容易敲错（中间就把两个文件的内容写混过一次），先保持最简单的版本。

## 八、下次再黑屏，按这个顺序来

1. **先确认系统活没活**：`Ctrl+Alt+F2` 能进终端，就别慌，也别反复硬断电；
2. **查显卡在不在**：`lspci -d 10de:`，空的就是显卡掉线；
3. **冷断电复位**：先 `set-default multi-user.target`，再 `poweroff`，拔两根电源线等 30 秒以上再开机；
4. **恢复图形界面**：确认 `xorg.conf` 是 NVIDIA 版本，`set-default graphical.target`，重启 lightdm；
5. **恢复业务**：跑启动脚本、启动反向隔离客户端、打开平台看视频。

预防上，根子在供电：这台主机要接可靠的 UPS，确需停电检修时先在系统里正常关机再断电，不要带电硬断，也不要反复硬断。如果以后**不断电也掉卡**，或者掉得很频繁，那就要怀疑显卡、插槽或供电线接触了，再找厂家查硬件。

## 写在最后

回头看，这件事最大的弯路是被"KVM 坏了"这个结论带着走。KVM 连不上是表象，信号源没了才是原因，换多少台 KVM 都没用。

几点体会：

- **先证明什么是好的**。能进终端、容器在跑、磁盘正常，范围一下就缩小到"图形显示"这一块；
- **用证据定位，不靠感觉**。`no screens found` → `xorg.conf` 指向独显 → `lspci` 里没有独显，每一步都有输出可以对照；
- **热重启不等于冷断电**。服务器的待机电会让很多"重启就好"的经验失效；
- **厂家的结论要追问"为什么"**。说不清原因的结论，大概率还没找到根子。

排查过程中，我是拍照片和视频给 AI 助手一起分析的：它负责根据输出提出假设、给出下一步命令，我在现场执行、反馈结果。这种分工对付这种设备不能联网、只能现场敲命令的情况，挺好用。
